# 採点 0.1.0 と根拠

採点バージョンは `oth-jp-rules-0.1.0`。同じ入力・観測日時・採点バージョンなら同じ結果になります。AIは呼びません。Starsは表示のみです。

|項目|配点|今回の規則|
|---|---:|---|
|Demand|20|限定Issueで英日需要語を検出した1件につき2点。コメント3件毎に最大2点、リアクション5件毎に最大2点を加算。合計20点上限。未取得はnull、取得済み検出0件は0点|
|Commercial Gap|20|90日以内の手動調査で提供あり3点、明記された調査範囲内の不検出12点。READMEの用語だけでは採点しない。その他null|
|Japan Gap|20|需要得点が正で、日本関連性・ローカライズ余地・競合調査の手動入力が全て存在する時のみ評価。日本関連性5点、その上でローカライズ余地5点、調査範囲内で競合未確認5点。広域Web調査不足の5点は付与しない|
|License|15|LICENSEファイルとGitHub SPDX識別を取得できた既知のライセンスのみ。MIT/BSD15、Apache14、MPL11、LGPL10、GPL7、AGPL4。ファイル未確認はnull、不明な権利はBLOCKED|
|Solo Feasibility|15|README中のGPU/kernel/distributed等の高負荷用語があれば2点。なければ明示CLIの手掛かりに8点。他はnull。コードの実装容易性を実証した点数ではない|
|Monetization|10|限定Issueに需要語があれば、CLIはGUI仮説、それ以外はSupport仮説に4点。支払意思未検証で残り6点は付与しない。検出なしはnull|

各項目に `value/max/reason/evidenceIds` を保存します。合計はnullを足さず、評価済み配点と未評価配点を別に示します。例えば暫定37点・評価済み60点・未評価40点を61.7/100点へ換算しません。

License不明、READMEの404、archived、fork、mirror、長期更新なし、手動のmalware/redistribution/source-availableリスクは除外記録とBLOCKED表示へ送ります。README取得失敗は404とは区別し、PARTIALと未評価へ送ります。更新なしは放棄の断定ではなく再確認を要する保守的な除外です。

評価済み配点60未満、需要未取得、需要0はLOW_SIGNAL。その他は原則VALIDATE。日本市場の根拠、確認済みライセンス、70点以上が揃う時だけ候補上のREADYとなります。**候補のREADYは法的適合性や収益性の保証でも、プロジェクトの公開準備状態でもありません。**

Confidenceは `評価済み配点/100 × 取得鮮度係数 × 市場範囲係数` を小数2桁で記録します。取得後30日以内の鮮度係数1、それ以外0.5。手動競合確認あり0.8、未確認0.6。成功確率として校正していません。Japan Confidenceは未評価LOW、手動の限定調査に基づく評価MEDIUMです。

限界: キーワード法は否定文・文脈・重複した要望・解決済み状況を理解しません。Issue一覧のPRは除外しますが、APIの1ページにPRが混ざれば調査Issue実件数は上限より減ります。READMEの日本語用語・リンク検出は日本語文書の品質確認ではありません。手動観測の最新1件を使い、過去の記録と自動合成しません。一次評価だけの案件には深掘り相当の点数を付与しません。
